# DSH 0.2.2-rc.5 compatibility analysis

This adaptation moves Research Graph from DSH `0.2.2-rc.3` to `0.2.2-rc.5` while preserving research-graph behavior, Workspace Folders, native Session backups, and existing profile data. The plugin version becomes `0.2.2-rc.5` under the new-DSH-line version policy.

## Scope and method

- Old upstream: `dsh-v0.2.2-rc.3`, commit `38a6a5c965aa99ab525161efb7cc5cf1fe62fced`.
- New upstream: `dsh-v0.2.2-rc.5`, commit `9c2670d3bce5275e0d1610272958121af87787bb`.
- The range contains 13 commits: DeepSeek refusal handling, LiveShare fixes and tests, model-route-dependent Web search defaults, and the rc.4/rc.5 releases.
- The analysis starts from `package.json`'s `dsh.client.inject`, direct dependencies and exact LLM peer, then scans `src/`, `types/`, `tests/`, `scripts/`, bundler externals, and `VENDORED.md`.
- Every consumed surface records **changed / unchanged / uncertain**. No uncertain rows remain after the compiler and runtime gates. Upstream line numbers below refer to rc.5.

## Dependency and release-age handling

All direct `@deepseek-ai/dsh-*` dependencies and the exact LLM peer move from rc.3 to rc.5. Node.js remains `>=24.9.0`; Cordis, Schemastery, and Zod remain unchanged. The rc.5 packages are inside pnpm's 24-hour release-age window during adaptation, so local commands and CI/Publish temporarily use `pnpm_config_minimum_release_age=0` with a removal deadline. The lockfile updates to the official rc.5 artifacts; this pnpm install did not add new `minimumReleaseAgeExclude` entries, so none are invented manually.

# Generate reviewable drafts from frozen discussion selections

Issue #7 uses the card editor introduced by #6. Preparing an extraction reads one exact continuous selection of completed direct discussion turns. A 500–64,000 character material budget admits a whole-turn prefix; an oversized first turn fails explicitly. The preview shows the original selection, exact included material and every omitted boundary. It never labels a partial selection as a full-session summary or claims to have read tool evidence.

The Host stores this Extraction Snapshot in `session_graph_knowledge.extraction_sources` before returning it. It is separate from saved cards and contains no generated results. This preserves the provenance of an open draft through a Host restart, including when the source later becomes unavailable. Regenerating from the same snapshot reads the same material. Generated text remains in the open browser view until explicitly saved.

Generation requires an explicit provider/model and calls the Harness LLM transport directly with the frozen material and a fixed extraction instruction. The source Session's recorded model route, or the configured plugin fallback, only pre-fills those choices. The call has a timeout, a 4,096-token output limit, a streamed-size bound, cancellation, and rejects non-text or unfinished output. It does not enter the source Agent loop or write Session logs.

All model output defaults to draft. Each citation must match complete included turn boundaries in the same snapshot. Invalid citations are counted and omitted from sources; a card with no valid sources is marked for verification. The editor allows text, status, and source correction by choosing included turns, with an exact original reader. Valid provenance is explicitly distinguished from correctness. Saving captures the addressed excerpt into an immutable Card Revision.

Every subsequent generation appends a separate batch. This preserves edited or failed-save drafts even while another generation runs or is canceled. The card editor retains a stable identity across retries. Public Host/Gateway and registered-view tests cover clipping, outside/invalid/absent citations, source persistence across restart, explicit save, cancellation, and edits surviving another generation. A separate model-quality record belongs to batch delivery and is descriptive, not a CI gate.

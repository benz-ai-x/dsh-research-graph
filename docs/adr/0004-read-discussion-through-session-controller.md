# Read Original Discussion through Session Controller

Issue [#3](https://github.com/benz-ai-x/dsh-session-graph/issues/3) adds Session History to the Selected Session's Inspector. Harness remains authoritative for discussion content. A package-owned, read-only History Remote calls public `sessionController.inspect(sessionId, signal)` for attached and cold persisted Sessions, without activating an Agent, using a model, or appending events. It does not reuse Digest generation.

Discussion Turns are delimited by `turn/start` and `turn/end` event sequences. The reader exposes text blocks from direct user messages and assistant messages, preserving their order and roles; it omits tools, attachments, reasoning, and plugin messages. An unfinished turn exposes status but no changing text or selectable fixed source. Exact Session identity and event boundaries locate a Discussion Source; titles, text similarity, and later appended events do not redefine it.

Normal requests return the latest ten turns or an adjacent page, with a maximum requested page size of twenty. An exact anchor starts at a recorded turn boundary. Rechecking a Discussion Source returns its complete selected range, even across pages, and reports whether earlier or later turns exist. The Host currently reads the full selected Session snapshot before slicing. This bounds normal browser page rendering, not persistence I/O or Host snapshot memory; storage-level paging would require another supported Harness interface.

Working Position can also address a completed range using only its start/end event boundaries. This request is exclusive of an anchor, adjacent-page cursor, or Discussion Source and uses the same exact completed-boundary validation as a source recheck. It returns the full range without an excerpt payload; an unreadable original or missing boundary returns `unavailable`. This restores long reading windows without storing discussion text in browser presentation state.

The browser keeps loaded turns and the Discussion Source in memory only while that reader is open. Ranges cannot skip unloaded or unfinished turns. A retained excerpt is an explicit fallback supplied with the selected boundaries: available original content always wins; a failed read or missing boundary produces `excerpt` only when that excerpt exists, otherwise `unavailable`. The UI labels these states and preserves source identity, including while a retry is pending or has failed. Empty readable history and transport failure remain separate user-visible states. This establishes no durable knowledge-card or excerpt store.

Each browser request owns an AbortController. Cancellation, switching Session or tab, and closing the reader abandon the request, and late replies are ignored. The Host combines caller and service-lifecycle cancellation, rejects canceled results, and waits for admitted reads to settle on disposal. The public Host method keeps `signal` as its final parameter: Harness source-mode Gateway discovery recognizes that exact name when injecting transport cancellation. A differently named parameter would be treated as a JSON argument and leave the Host without its signal. Shared lightweight strict codecs validate the public wire shape without bundling Host dependencies into the browser. Reading and selection do not change the Viewed Session; only an explicit Open session action invokes Harness navigation, without claiming native chat scroll positioning.

Acceptance tests exercise the registered Graph UI and the public Host service, including real cold JSONL history, duplicate text across Sessions and turns, exact range rechecks after append, paging, unfinished turns, excerpt fallback through retry and transport failure, mixed-content filtering with ordered user/assistant text, and cancellation races. These are the two TDD boundaries confirmed by the user.

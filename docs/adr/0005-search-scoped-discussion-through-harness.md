# Search Scoped Discussion through Harness

Issue [#4](https://github.com/benz-ai-x/dsh-session-graph/issues/4) adds Discussion Search beside the Graph's existing Title Filter. Harness remains authoritative for session identity, Workspace membership, archive state, and original text. The browser requests a scope and archive policy; it never supplies an authoritative candidate list.

A package-owned Search Remote resolves candidates from public `sessionQuery.listSessions` and `workspaceRegistry`, excluding Subagent Sessions. Workspace eligibility follows the graph's membership-or-directory rule; Directory Scope uses an exact directory match. Allowed IDs constrain Harness `searchSessions` before its pagination. Only completed direct user/assistant text verified by public `sessionController.inspect` contributes results, using the same Discussion Turn projection as the Original reader.

DSH `0.1.5-alpha.1` uses an opt-in SQLite `unicode61` index. It does not match an arbitrary substring inside an uninterrupted Chinese token. After a successful real index call, queries containing Han characters therefore verify all eligible originals for normalized literal substring matches. Other queries verify the index's candidates. This preserves an explicit disabled state and uses the Host search infrastructure without a second index or model. The tradeoff is full-snapshot I/O across the eligible sessions for Chinese queries; paging bounds browser rendering, not initial Host search cost. Read failures surface as retryable failures rather than silently claiming complete results.

Each Session contributes its latest matching message in a completed Discussion Turn. Results sort by message time descending, with Session ID as tie-breaker; metadata includes workspace/directory, archive state, time, and a bounded excerpt. Result identity comprises Session ID, message sequence, and turn-start sequence. The shared Original reader opens that exact turn and exposes adjacent history; an unavailable original does not turn the retained search snippet into verified original text.

Continuation uses short-lived Host-memory snapshots, at most four for five minutes, with opaque cursors bound to query, scope, page size, session candidates, workspace metadata, and archive state. New results do not reshuffle an existing snapshot. Expiration, eviction, or changed scope facts asks the user to restart. Snapshots persist neither full originals nor generated material.

The Search Inspector is independent of Canvas selection. Reading archived or cross-workspace results changes neither Canvas eligibility nor the Viewed Session. Only explicit Open session navigation changes the viewed conversation. Query/scope changes, cancellation, and closure abort pending work and suppress late replies. The Host combines caller and lifecycle cancellation and waits for admitted work on disposal. Every Remote keeps `signal` as its final parameter for Harness Gateway discovery. SQLite statements themselves retain the upstream engine's synchronous cancellation limits.

README setup overrides `session-query-sqlite` with both `path` and `openAt: first-search`, since a Cordis patch replaces the whole configuration. The product distinguishes disabled, preparing/searching, failure, and no results. Strict wire codecs and the registered Graph UI use the same public Search contract; actual matching Harness compiler checks exclude standalone adapters. Public Host tests exercise real SQLite and Gateway behavior, and packed-profile acceptance verifies an enabled Chinese search and original event identity without source mutation or model use.

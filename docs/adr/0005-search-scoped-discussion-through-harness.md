# Search Scoped Discussion through Harness

Issue [#4](https://github.com/benz-ai-x/dsh-session-graph/issues/4) adds Discussion Search beside the Graph's existing Title Filter. Harness remains authoritative for session identity, Workspace membership, archive state, and original text. The browser requests a scope and archive policy; it never supplies an authoritative candidate list.

A package-owned Search Remote resolves candidates from public `sessionQuery.listSessions` and `workspaceRegistry`, excluding Subagent Sessions. Workspace eligibility follows the graph's membership-or-directory rule; Directory Scope uses an exact directory match. Allowed IDs constrain Harness `searchSessions` before its pagination. Only completed direct user/assistant text verified by public `sessionController.inspect` contributes results, using the same Discussion Turn projection as the Original reader.

DSH `0.1.5-alpha.1` uses an opt-in SQLite `unicode61` index. It does not match an arbitrary substring inside an uninterrupted Chinese token. After a successful real index call, queries containing Han characters therefore verify all eligible originals for either normalized literal substrings or indexed phrases. The literal check supplements phrase matching, so mixed queries such as `修复 foo bar` still find `修复 foo-bar`. Other queries verify the index's candidates for phrase matches. This preserves an explicit disabled state and uses the Host search infrastructure without a persistent plugin index or model. The tradeoff is full-snapshot I/O across the eligible sessions for Chinese queries; paging bounds browser rendering, not initial Host search cost. Read failures surface as retryable failures rather than silently claiming complete results.

PR #15 review found that literal verification discarded valid indexed phrases such as `foo bar` in `foo-bar` and `cafe` in `café`. Trusting an indexed event alone would also admit tool-call content embedded in an otherwise readable assistant message. The correction replaces the earlier no-second-index implementation choice with a query-local in-memory SQLite FTS5 matcher using the same `unicode61` tokenizer and escaped phrase expression as the matching Harness. It checks one extracted direct discussion text at a time, after excluding unfinished turns and non-discussion blocks. SQLite supplies the actual match position for the excerpt. The temporary database is closed on success, failure, or cancellation; it never persists a corpus or changes the Host index or sources. This avoids maintaining an approximate tokenizer in JavaScript.

Each Session contributes its latest matching message in a completed Discussion Turn. Results sort by message time descending, with Session ID as tie-breaker; metadata includes workspace/directory, archive state, time, and a bounded excerpt. Result identity comprises Session ID, message sequence, and turn-start sequence. The shared Original reader opens that exact turn and exposes adjacent history; an unavailable original does not turn the retained search snippet into verified original text.

Continuation uses short-lived Host-memory snapshots, at most four for five minutes, with opaque cursors bound to query, scope, page size, session candidates, workspace metadata, and archive state. New results do not reshuffle an existing snapshot. Expiration, eviction, or changed scope facts asks the user to restart. Snapshots persist neither full originals nor generated material.

The Search Inspector is independent of Canvas selection. Reading archived or cross-workspace results changes neither Canvas eligibility nor the Viewed Session. Only explicit Open session navigation changes the viewed conversation. Query/scope changes, cancellation, and closure abort pending work and suppress late replies. The Host combines caller and lifecycle cancellation and waits for admitted work on disposal. Every Remote keeps `signal` as its final parameter for Harness Gateway discovery. SQLite statements themselves retain the upstream engine's synchronous cancellation limits.

When live Workspace updates remove the selected scope option, a layout effect clears the old results and Inspector, aborts pending work, and resets to the Viewed Session's available scope before painting. Keywords remain. This also covers a Directory Scope becoming a Workspace Scope and an unavailable scope falling back to all Host sessions. A valid explicitly selected scope survives unrelated Workspace updates.

README setup overrides `session-query-sqlite` with both `path` and `openAt: first-search`, since a Cordis patch replaces the whole configuration. The product distinguishes disabled, preparing/searching, failure, and no results. Strict wire codecs and the registered Graph UI use the same public Search contract; actual matching Harness compiler checks exclude standalone adapters. Public Host tests exercise real SQLite and Gateway behavior, and packed-profile acceptance verifies Chinese substrings, punctuation, accents, mixed-language phrases, and original event identity without source mutation or model use.

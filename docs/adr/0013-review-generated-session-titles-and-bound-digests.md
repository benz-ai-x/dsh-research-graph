# Review generated Session titles and bound digest reading length

Session Title Suggestions reuse the digest's bounded discussion selection and recorded model route, through a separate explicitly invoked Remote. They are temporary, read-only model projections and do not reuse the native automatic title refresh, which would immediately change and unpin an existing title. Applying an editable suggestion uses the public Session binding rename. DSH owns the saved title, its user-title event and normal list/projection propagation. The graph does not keep a competing authoritative title.

Generation is cancellable on close, explicit cancellation and selection change; late responses cannot populate another Session. Save uses the captured Session identity. Before applying, the Client checks the latest listed title against the reviewed starting title; native rename does not expose an atomic compare-and-set, so this is a preflight check, not a cross-client locking guarantee. A failed save retains the suggestion, and a matching authoritative feed update can confirm an uncertain reply. Applying deliberately pins the title as a user title. Unavailable or archived topic references do not offer rename.

Digests retain their existing structured overview/keyOutcomes/openItems contract. The prompt requests one overview sentence and short list items with restrained inline Markdown emphasis; the existing Harness renderer handles their display. Limits are 140 Unicode characters for the overview, 160 per point, five outcomes, three open items and 1,000 total characters including Markdown. The intended reading length is shorter: 200–350 Chinese characters or 100–160 English words.

Complete but oversized JSON triggers at most one additional model request with tighter brevity instructions. It does not truncate the text or Markdown. A second oversized result fails without replacing a previous valid digest or caching partial output. Transport, malformed JSON and max-token failures retain the explicit retry behavior of ADR 0002. The default 4,096-token model output budget remains available for reasoning; it is not the reading-length limit. Both auxiliary capabilities use the same configured per-request timeout and model route policy. Sources, cancellation and provider shutdown continue through the existing public Host seams and matching Harness checks.

# Record Merges as Independent Session Projections

A Merge creates an independent, unparented target Session and records its provenance by pairing an explicit Merge marker with Harness-owned Session Snapshot references in the same model step. The marker uses `user/message` with the public `plugin` source, plugin name `dsh-session-graph`, and a `notice` summary. Its final text block carries the versioned operation ID and ordered source IDs. Both the event type and source fields must satisfy the Harness format catalog; adding custom fields to the source is not supported. A versioned projection and durable Projection Cache expose the Merge Relation after replay or restart.

The Host re-inspects the target and every source at submission time: sources must still be non-blank, non-archived Canvas Sessions in the target directory, and a non-blank target is accepted only when its first Merge marker binds the exact same ordered sources. Browser-provided eligibility is advisory only. Once a matching capture reaches the durability commit, ownership transfers from the Remote caller to the Host; caller disconnection no longer cancels that commit, and a commit failure remains a stable persistence failure. Retries reuse the target and durability barrier; an earlier operation's late capture is accepted only when its ordered source identities match the retry exactly.

Historical releases wrote `source.kind = 'session-graph-merge'`. Harness `0.1.5-alpha.1` rejects this source during V0/V1/V2 migration, before the plugin's projection can run. The projection retains its legacy reader for already readable logs. The offline `dsh-session-graph-migrate` command repairs only recognized plugin markers, runs the official full format migration and validation, and optionally writes a separate V3 artifact without overwriting any file. It never runs automatically during graph browsing or Host startup. See the [recovery instructions](../../README.md#recover-historical-merge-sessions).

# Recover Historical Branches by a reserved native identity

Issue #32 prioritizes graph exploration: choose one completed Discussion Turn in Workspace, directory or topic Original, preview the child title and inherited range, then create a recoverable Branch. A five-turn source cut at turn 2 must retain exactly its first two completed turns without modifying the source. Missing, incomplete or changed cuts must fail before creating a child.

The matching DSH RC.2 Session Controller chooses a new identity inside `fork` and cannot accept a caller-reserved target. Repeating that command after a lost response can create a second child. The plugin instead journals a reserved target and canonical hash of the exact inherited prefix, constructs the child with public `sessions.prepare`, durably writes that seed with Session Persistence, and uses native `sessionController.create` to adopt the same identity and compose its Agent. Native rename and topic writes finish the operation. Source preset and cwd are retained; the source Workspace is attached when available. The inherited cut extends through between-turn events to the next `turn/start`, matching native alignment.

Native alignment can include inbox admissions for the next source turn, and DSH's inbox projection replays inherited splices. The packed-profile regression demonstrated that an untouched child could execute that old pending question when the user submits a new one. Before persisting or activating the child, the plugin folds the public `agent/inbox/spliced` event counts and appends native canceled splices to the child's own suffix. The inherited prefix remains byte-equivalent, while pending source work cannot execute in the child. This is an intentional extension to the native Branch workflow, not a change to the source queue.

Preparation creates no Session or Agent. Submission rechecks the prefix until the immutable seed is journaled; after that boundary the Host completes the durable transaction despite browser cancellation. A prepared record can already have a persisted child after a journal outage. Retry reads that exact identity, validates its header and prefix, writes only a missing suffix, and finishes adoption/name/topic association. Header comparison normalizes the released persistence default `delegationDepth: 0` and ignores JSON object-key ordering. A conflicting target is never overwritten. Once ready, retries return the receipt without another action. The `created` receipt is written after native adoption acknowledges the target, before naming and topic association. The released `session/workspace-attach-failed` error also acknowledges adoption when its structured Session and Workspace identities match this exact create request; the journal retains `created` together with the error, so the child remains explicitly openable while Workspace attachment is recoverable. The same native create request idempotently adopts that identity on retry, then completes Workspace attachment, naming and topic association without rewriting any continuation already added to the child. Generic creation errors or errors addressing another identity do not prove adoption; a persisted seed without that acknowledgement stays `prepared`. Opening the child is explicit. Creating another Branch requires a fresh operation.

The journal is Host-owned; the browser remembers the operation identity for the same source/cut/topic and restores focus to the Original action on close. Successful topic attachment refreshes topic references so the actual parent-child relation appears. Background topic-list refresh retains the mounted graph and reader, preserving the return trigger through asynchronous loading or failure. Canvas identity follows the current topic, so refreshed membership updates the graph without remounting that reader. Host and rendered-view tests cover changed cuts, naming/topic failures, durable seed with an unwritable journal, restart, one target identity and delayed membership after returning to the Original. Packed acceptance uses real Agents for five-to-two inheritance and independent continuation, including the inherited pending-input regression.

# Bind a material preview to one native admission identity

ADR 0015 extends this decision's original single-turn material limit to a continuous completed-turn range and adds Synthesis over frozen materials. The admission and retry guarantees below remain in force.

Issue #8 creates independent discussions from one to three explicitly ordered Research Materials. A material is an immutable Card Revision or one complete direct Discussion Turn. The Host captures the addressed revision/range, verifies the target Workspace identity, builds the exact message and applies a 32,000-character total message budget. Card materials include card text and provenance labels; original text requires its own turn selection. Over-budget material, incomplete or multiple turns, duplicate selections, and embedded `dsh-session:` references fail explicitly rather than silently expanding or cropping context.

The matching Harness `0.1.5-alpha.1` public Session Controller supports caller-specified Session identities in `create` and persists a prompt `requestId` on accepted user messages as `source.rpcId`. Native prompt admission checks both the live inbox and user/message history before admitting an already-seen request. This protocol is used directly; SessionReferenceInput is not used to stand in for cards or ranges. The actual Agent/model request comparison is part of packed-profile batch acceptance.

The `session_graph_reuse.attempts` domain stores an immutable preview and an admission journal. Preparation reserves stable, Host-minted target and request identities before any Session is created. A command hash makes repeated preparation idempotent and rejects changed content under an existing preview identity. Submit serializes changes, creates or adopts the same target, records target creation, and invokes native prompt admission with exactly the preview text. Workspace identity/path changes require another preview.

Only an acknowledged native admission becomes `accepted` and gains an acceptance timestamp. A created target with a failed or uncertain submission is shown as pending, with Open and Retry actions. Retrying uses the same target and native request identities; an accepted record is returned without another prompt. A disconnect after admission does not prevent the Host from persisting the receipt. If that durable write fails, the caller receives uncertainty and can retry through native deduplication. Model completion is deliberately separate from admission.

The browser holds the editable material list, order, question, Workspace and uncertain attempt while the Graph remains open. Inputs lock once a target has been created, preserving the reviewed retry payload. Accepted/pending target records can also be reopened from the target Session's Graph, using Host storage rather than browser cache. The read view displays explicit Reuse Relations and the frozen text; it never claims these records are Branches or Merges or changes source ownership.

Inputs also stay locked after submission begins until a complete response or recovery read establishes the result. Transport rejection triggers a read of the same operation journal; cancellation preserves uncertainty until the composer is reopened or explicitly rechecked. Recovery reads serialize behind admitted submissions, including uncancellable Session creation, so an in-progress attempt cannot return a stale no-target result. Failed recovery keeps the frozen payload and reserved target identity; it never invents an acknowledgment. Reopening after cancellation does not navigate automatically.

A prepared journal can outlive native creation when storage rejects both the creation and failure writes. Recovery reads, repeated preparation, and target history therefore inspect the reserved Session identity before reporting `targetCreated: false`. An empty `session.page` cut checks existence without starting an Agent or returning source text. Only its stable `session/not-found` error code establishes absence; other read failures preserve uncertainty. Error classification uses the public code because constructor identity can differ between the installed plugin and Host module copies. A readable target is returned with `targetCreated: true` even while journal storage remains unwritable, without writing during recovery. Its stage stays `prepared` until retry completes native adoption and Workspace attachment, then persists creation before sending. This also recovers older prepared records after Host restart.

Targeted public Host/Gateway tests cover card-only boundaries, exact historical revisions after edits, one/three/four material cases, total budget refusal, failed creation, uncertain admission, stable retry identities, receipt recovery and source non-mutation. Registered Graph tests verify preview before admission, explicit target Workspace, failure recovery and navigation only after acknowledgment. The complete profile fixture additionally checks exact material text in the real model request and one durable user message after repeated submit; this runs once with the full batch's archive.

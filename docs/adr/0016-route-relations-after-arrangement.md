# Route research relations after Session Arrangement

Workspace and Research Topic graphs use one synchronous dependency layout over intact Branch clusters. Strongly connected components retain a stable internal order and all actual directed relations; only disconnected components may wrap. Both expanded and compact cluster sizes reserve space. Placement reduces avoidable crossings without treating Merge, source, reuse, or synthesis relations as Branch lineage.

When connected research components coexist with multiple independent discussions, the independent frames pack as a separate block. They can wrap within that block, but do not scatter beside source rows. Branch frames remain intact.

Cluster titles use short tabs showing the Branch cluster's member count; the full root title remains available on hover. UI and routing share the tab width, leaving the middle of the upper boundary open to incoming relations. The group outline is not an obstacle. This avoids forcing every incoming relation around the entire cluster just to reach its root card.

The canvas presentation seam routes connections after manual positions, collapse, and whole-cluster offsets. It returns paths, relation terminals, arrowheads, labels, and complete bounds together. Short orthogonal channels use a spatial obstacle index; blocked routes use a bounded rectilinear search. Manual card overlap can make a terminal unreachable, in which case the relation remains visible and Relayout restores spacing. Arbitrarily dense graphs may still have crossings.

Obstacle checks use the final distributed terminal positions. Clear seats remain stable; blocked seats use free intervals or another side without taking an existing seat. Candidate route costs include reserved collinear segments. When the best detour still overlaps, the router tries another departure row and then a bounded local search, retaining the lower-cost clear route. If the ordinary local search still overlaps, one further bounded search adds a midpoint between coordinates less than one channel width apart. This admits a free arrival row in the six-pixel padded gap between a compact cluster title and its first card. Already clear routes retain their ordinary grid and path; the extra route is accepted only when its length plus overlap cost is lower. It does not expand every candidate into every departure row, which would multiply routing work during dense-graph dragging.

We evaluated ELK Layered 0.12.0: its bundled browser file was 1,609,707 bytes, and local 4/100/1,000-node examples took 31/25/135 ms. Its Promise/worker layout integration would not replace the fixed-position rerouting needed after every drag, so this change keeps the existing synchronous pipeline and adds no runtime dependency. See the [ELK integration notes](https://github.com/kieler/elkjs) and [Layered capabilities](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html). These measurements are local observations, not a browser performance guarantee.

Relayout keeps one in-memory undo of manual placement. Repeating it preserves the useful undo; another committed arrangement action or scope change expires it. Selection, reading state, collapse, viewport scale, and pan remain intact. Fit changes the viewport to include the graph and its routed relations; Reset also clears collapse before fitting. Relayout and its available Undo action remain directly accessible in the canvas toolbar. Topic changes remain local drafts until explicit Save arrangement, as in [ADR 0006](0006-persist-research-topics-through-host-storage.md) and [ADR 0010](0010-host-scoped-working-position.md).
